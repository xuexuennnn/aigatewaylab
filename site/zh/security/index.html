安全

网关运维里那些在顺风演示里看不见、在事故中起决定作用的部分。

密钥保管

秘密放在哪里绝不允许出现在哪里
服务商密钥 (sk-…)宿主机上 0600 的 env 文件，或密钥管理服务；仅网关进程用户可读日志、报错正文、客户端响应、git、容器镜像、明文备份
虚拟密钥 (vk-…)在网关数据库中散列存储创建之后的任何完整展示——UI 只做一次性展示，日志只记前缀
管理员凭证密码管理器；开启 TOTP 共享聊天、仓库里的 .env 文件

最小权限

  • 容器以专用非 root UID 运行，根文件系统只读，临时空间走 tmpfs。
  • 管理面绑定 localhost；访问它需要 SSH 隧道或 VPN 成员资格。公网接口只承载推理流量。
  • 数据库用户运行期没有 DDL 权限；迁移作为独立步骤执行。
  • 每个客户团队有自己的虚拟密钥，带模型白名单与预算——吊销一个客户绝不波及另一个。

日志脱敏

网关位于请求路径上，它的日志天然是个蜜罐。部署时做了如下脱敏：

  • Authorization 头 → vk-****后4位
  • 提示词与补全正文 → 默认只记录 token 数；除非客户为调试显式开启内容日志，且带 TTL
  • 上游报错正文 → 服务商密钥在错误到达客户端或日志之前被剥离

演示里的请求日志展示的正是这个形态：足够运维，不值得偷。

恢复流程（排练过的，不是纸上谈兵）

事故响应
虚拟密钥泄漏吊销该密钥（请求 fail-closed），复查其使用窗口的审计日志，按同样策略补发新钥。爆炸半径：这把密钥的配额。
疑似服务商密钥泄漏在服务商侧轮换，更新密钥库条目，重启网关（重试代理挡住的几秒停机），用金丝雀请求确认。
疑似主机沦陷冻结：先在服务商侧吊销服务商密钥——那才是王冠。用干净镜像加加密备份重建；绝不从沦陷主机恢复可执行文件。
数据丢失恢复昨夜加密转储；转储之后的用量记录确认丢失并如实承认——账务以服务商控制台对账。
